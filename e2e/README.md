# Тестове за новите функции (преди прод)

Playwright срещу локалното приложение. Тестовете ползват **своя база `pakto_e2e`** (изгражда се наново при всяко пускане от миграциите и `db/seed.sql`) и **свой dev сървър на :3100**, затова не пипат данните зад `http://localhost:3000`.

Нужно: `pnpm db:up` (Postgres + Mailpit през Docker/OrbStack), `.env.local`, и Chromium за Playwright (`pnpm exec playwright install chromium`, ако липсва).

```bash
pnpm test:e2e                      # всички
pnpm test:e2e e2e/03-*.spec.ts     # един файл
```

Пускат се само по сигнал на собственика.

### 5. Етапи и плащания без оферта (Р)
Проект → „Етапи без оферта“ → „Добави етап“ (име, срок) → плащане към етапа; планът за плащане се брои като договорена цена, последният етап задава срока, клиентът ги вижда в портала, вноска може да се повтаря всеки месец.

### 6. Приемане на завършен етап (Р)
Екипът пита клиента за етап → писмо с „Строй Дизайн завърши етап „X“ и очаква да го приемете“ → клиентът приема с код от писмото или праща бележки → плащанията към етапа стават дължими в деня на приемането. Без пълен портал екипът записва приемането сам.

### 7. Малки въпроси към клиента (Р)
Екипът задава избор без цена → клиентът отговаря в портала → отговорът се вижда в проекта; повторен отговор не променя записания.

### 8. Сигурност и пълнота (Р)
Данните на друга фирма не се виждат (организация във всяка заявка); клиентски линк не отваря чужд проект; миграциите минават върху копие на прод (`pnpm db:pull`) преди deploy; нова миграция `20261123200000` е последна и без дублирани версии.
